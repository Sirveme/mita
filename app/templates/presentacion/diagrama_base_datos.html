🔗 RELACIONES ENTRE TABLAS

1:N usuarios → tecnicos (Un usuario puede ser técnico, pero no todos los usuarios son técnicos)
1:N tecnicos → tecnicos_horarios (Un técnico tiene múltiples horarios por día de semana)
1:N usuarios (cliente) → servicios (Un cliente solicita múltiples servicios)
1:N tecnicos → servicios (Un técnico atiende múltiples servicios)
1:N servicios_tipos → servicios (Un tipo de servicio tiene múltiples instancias de servicio)
1:N usuarios (cliente) → vehiculos (Un cliente puede tener múltiples vehículos)
1:1 servicios → pagos (Un servicio tiene UN pago asociado)
1:N usuarios → notificaciones (Un usuario recibe múltiples notificaciones)
1:N servicios → mensajes_chat (Un servicio tiene múltiples mensajes de chat)
1:N usuarios → mensajes_chat (Un usuario envía múltiples mensajes)

📝 NOTAS IMPORTANTES

  • usuarios.rol → ENUM('cliente', 'tecnico', 'admin', 'proveedor')
  • servicios.estado → ENUM('pendiente', 'preautorizado', 'buscando_tecnico', 'asignado', 'en_proceso', 'completado', 'cancelado')
  • pagos.estado → ENUM('pendiente', 'preautorizado', 'confirmado', 'rechazado', 'reembolsado')
  • pagos.metodo_pago → ENUM('culqi', 'yape', 'plin', 'efectivo')
  • notificaciones.tipo → ENUM('info', 'success', 'warning', 'error', 'servicio')
  • mensajes_chat.tipo → ENUM('texto', 'imagen', 'audio', 'ubicacion', 'sistema')
  • tecnicos_horarios → Un técnico puede tener múltiples registros (uno por día de semana)
  • servicios.tecnico_id → NULL hasta que un técnico acepte el servicio
  • Usar PostgreSQL en Railway (no SQLite)
  • Timestamps con timezone (TIMESTAMP WITH TIME ZONE)
  • Índices en: codigo, placa, email, fecha_programada, estado
